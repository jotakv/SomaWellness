# Framework de validación digital

> **Estado del documento:** blueprint interno. Salvo decisiones de diseño expresamente marcadas, las propuestas comerciales, problemas, efectos y adopción son **HIPÓTESIS**; los datos no disponibles son **PENDIENTE**. No acredita demanda, clientes, ventas ni viabilidad.

## Gates obligatorios

```text
Problem evidence → manual solution → Customer Zero → usage → measurable value
→ external pilot → willingness to pay → repeatable adoption
```

Cada feature registra hypothesis ID, segmento, evidencia a favor/en contra, baseline, métrica, umbral previo, coste, owner y decisión. Customer Zero prueba operación propia, no generalización. Un piloto gratuito no prueba pago. Network effect requiere que el valor por participante aumente de forma medible al añadir participantes, no solo más funcionalidades.

## Puerta de validación

No avanzar por entusiasmo: evidencia del problema → solución manual → Customer Zero → uso → valor medible → piloto externo → disposición a pagar → adopción repetible. Registrar evidencia adversa y detener o reordenar si no se supera la puerta.
