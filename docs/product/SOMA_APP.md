# SOMA App / Web App

> **Estado del documento:** blueprint interno. Salvo decisiones de diseño expresamente marcadas, las propuestas comerciales, problemas, efectos y adopción son **HIPÓTESIS**; los datos no disponibles son **PENDIENTE**. No acredita demanda, clientes, ventas ni viabilidad.

## Web/PWA primero

Secciones futuras: **HOME, TODAY, JOURNEY, EXPLORE, COMMUNITY, PROFILE**. No app nativa todavía. HOME responde “What should I do today?” combinando Journey, disponibilidad, catálogo, contenido, experiencias cercanas e historial, siempre con explicación y control del usuario.

MVP recortado: autenticación, Today, catálogo/availability, booking y preferencias. Offline, push, native sensors y social complejo quedan fuera. Métricas: task completion, experience completion, repeat y accesibilidad; no claims médicos.

## Puerta de validación

No avanzar por entusiasmo: evidencia del problema → solución manual → Customer Zero → uso → valor medible → piloto externo → disposición a pagar → adopción repetible. Registrar evidencia adversa y detener o reordenar si no se supera la puerta.
